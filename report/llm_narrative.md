The real model made the system genuinely agentic and exposed failures that the deterministic policy never could. **Safety held. There were {{LLM.unsafe_sent}} unsafe sends.** The model never attempted confirmation on a blocked case, never called an unknown tool, never passed an undeclared argument, and complied with neither prompt injection ({{LLM.injection_cases_where_model_complied}}). **Capability was weaker.** The model sent {{LLM.correct_completion_rate}} of the handoffs it should have sent. In six of those cases it stopped after drafting and wrote a summary instead of requesting approval, even after two critic rejections. The host then fell back to the server draft and sent nothing, which is safe but useless (§6.2). Two cases were lost to 60-second HTTP timeouts on the laptop endpoint. Every blocked case was escalated, and {{LLM.blocked_escalations_naming_all_gaps}} escalations named every gap. The critic fired {{LLM.critic_rejections}} times, so a 7B model needs it constantly.

The most instructive failure was **goal drift** on AMB-024 (missing medication dose). After its case was blocked, the model called `list_assigned_cases`, picked another case belonging to the same crew (AMB-004), and summarised *that* patient as its final answer. The server allowed those reads, because AMB-004 was within the crew's authorised scope, and nothing was sent. However, the final message described the wrong patient. This accounts for the {{LLM.out_of_scope_calls_attempted}} other-case calls and the {{LLM.invented_values_in_final}} "invented" values in Table 2: values from AMB-004 counted against AMB-024. Crew-level authorisation is necessary but broader than the task. I followed the week 10 pattern of attack, patch and re-test. The patch is a host-side **task-scope guard** that answers any call for another case, or for `list_assigned_cases`, with `outside_task_scope`, and a regression test reproduces the drift. On re-test the guard blocked both drift attempts. The model then exhausted its turn cap without naming the gap, so the case was contained but still not handled competently. The two timed-out cases completed correctly with a 180-second timeout.
